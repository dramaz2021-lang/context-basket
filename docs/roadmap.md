# 开发计划

所有项目初始状态为待开始。时间按一名熟悉 macOS 的开发者估算，交付兼容性验证后可调整。

## M0：验证整体交付（1–2 天）

- [ ] 建立 `Package.swift` 和两个目标的最小可构建实现。
- [ ] 准备合成的 3 段文字、3 张图片，其中一个问题需要综合图文才能回答。
- [ ] 生成 `context.txt` 和带编号的图片附件。
- [ ] 在原生窗口中加入整组拖出区域。
- [ ] 测试 ChatGPT 网页的 Chrome、Safari 入口，以及桌面端。
- [ ] 验证附件完整性、取消、重试、文件存活期和材料对应关系。
- [ ] 记录测试版本、操作步骤和结果，确定首发支持入口。

**通过条件：** 至少一个明确支持的入口可用一次拖拽添加完整图文材料；提问后能正确使用文字和图片。未通过时继续解决交付问题，暂不进入完整采集开发。

## M1：采集闭环（3–4 天）

- [ ] 当前材料组模型与本地恢复。
- [ ] 剪贴板文字、链接、图片采集，以及权限状态。
- [ ] 授权截图目录监听及文件就绪判断。
- [ ] 手动拖入图片、格式归一化、短时间跨来源去重。
- [ ] 暂停和关闭停止采集，识别隐藏内容标记。

**通过条件：** 从至少三个应用收集核心场景的材料，内容准确；权限拒绝和快速连续复制的行为有明确结果。

## M2：浮窗使用体验（3–4 天）

- [ ] 置顶浮窗、展开/折叠、材料计数和新增反馈。
- [ ] 预览、删除、排序、可选备注。
- [ ] 区分窗口移动和整组拖出。
- [ ] 将 M0 导出流程接到真实当前材料组。
- [ ] 拖出后保留当前组；新建收集可以开始下一组。

**通过条件：** 用户可在原应用持续工作，完成采集、整理和整组交付，过程中浮窗不抢走输入焦点。

## M3：稳定性（3–4 天）

- [ ] 文件丢失、未写完、格式不支持等异常处理。
- [ ] 持久化失败、崩溃恢复、导出快照清理。
- [ ] 取消拖拽、目标端拒收、部分上传失败后的重试。
- [ ] 多显示器、全屏应用、睡眠恢复。
- [ ] 按实现补齐关键测试，并在 macOS CI 中运行。

**通过条件：** 有代表性的异常不会静默丢失材料；状态反馈符合实际，重试可用。

## M4：内测分发（2–3 天）

- [ ] 应用图标、构建和打包脚本。
- [ ] 使用开发者账号完成签名、公证和安装包验证；账号条件单独确认。
- [ ] 在真实工作场景中试用，记录完成率、额外操作和失败原因。
- [ ] 发布注明系统及目标端兼容范围的内测版本。

第一轮不把付费账号申请、公证服务等待或重大兼容性返工计入上述开发时间。
