# 第一版产品说明

## 核心场景

用户从浏览器复制两段资料，从聊天软件复制一段要求，截取两张界面，再拖入一张参考图。收集期间继续操作原应用；整理后，一次拖入 ChatGPT，再输入需要综合这些材料的问题。

第一版面向 macOS。首发支持的 ChatGPT 入口由 M0 实测确定。

## 范围与交互

| 环节 | 约定 |
| --- | --- |
| 开始 | 首次完成必要授权后，打开浮窗即收集此后产生的内容 |
| 采集 | 文字、链接、剪贴板图片、系统截图、手动拖入的图片 |
| 反馈 | 显示材料计数和预览；收进新材料时不抢键盘焦点 |
| 暂停 | 暂停停止采集；关闭浮窗也停止采集并保存当前组 |
| 折叠 | 保留收集状态和明确可见的状态标记 |
| 整理 | 预览、删除、排序，可选的一句材料说明 |
| 交付 | 专用“全部材料”拖出区域；移动窗口使用独立区域 |
| 后续 | 拖出后保留材料，支持补充和再次拖出；新建收集开始下一组 |
| 恢复 | 重启后恢复当前组，明确呈现当前是否在收集 |

第一版只维护一个当前材料组。历史资料库、多组管理、云同步、自动摘要和其他 Agent 适配安排在后续评估。

## 材料与 Agent 的关系

- 原文按用户排列顺序进入 `context.txt`，来源仅记录可确认的信息。
- 每项材料有稳定标识；每次导出生成连续编号，并将图片文件名映射到对应材料。
- 用户的材料说明一并导出，例如“这是当前页面”“这是参考设计”。
- 图片作为独立附件保留清晰度；原图与缩略图分开保存。
- 资料中的文字作为参考内容组织，不擅自添加用户未提出的任务。
- 目标端附件显示顺序可能变化，材料关系以索引和文件名对应为准。

## 采集和存储细节

- 用户授权的截图目录可配置；文件写入完成后再入篮。
- 同一截图同时通过剪贴板和目录进入时进行短时间窗口内的去重。
- 保留用户主动重复添加的能力，不按内容永久去重。
- 来源不明时留空；前台应用仅可作为不确定的观察信息，不当作事实导出。
- 剪贴板权限不可用时显示状态，手动拖入仍可使用。
- 遵守剪贴板中的隐藏内容标记，暂停时停止读取新内容。
- 本地保存采集结果；运行数据不进入仓库或诊断日志。

## 完成标准

核心场景的 6 项材料均被收集，文字准确、图片清晰、顺序与对应关系保留。一次拖出能在已声明支持的入口完成添加，用户不需要逐项补传。取消或失败后材料仍可再次交付。

界面只能报告实际可观察的状态；系统拖拽结束不能被描述为目标应用上传成功。
